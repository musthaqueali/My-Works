Loading ASI Loadsheet
Overview
ASI loading requires tactics to be up to date in the ASM (Asset Strategy Management) module. Tactics will be linked from the ASM Strategy to create ASI Packages and SAP Maintenance Plans within those ASI Packages. This procedure will outline how to build the ASI Loadsheets for four tactics, NDE, External Visual, Internal Visual, and PSV Tactics.
The loading step is the same regardless of the contents of the ASI Loadsheet, and uses a tool created by Amplify. This tool is provided in the resource folder and must be run on an RTK laptop or remote desktop connection to the RTK network.
The ASI Family loadsheet is a comprehensive way to edit fields within ASI in mass. This is most used directly after using the Amplify Loading Tool to populate missing fields.
Multiple resources are referenced in this procedure, which are expanded upon at the end of this procedure and are resource folder.
ASI Packages are linked to ASM Strategies, and within the ASI Packages are SAP Maintenance Plans that corelate to each action in ASM. The hierarchy of these Maintenance Plans are shown below, and this information is what is populated in the “Package Strategies” Tab.
In addition, the Maintenance Plan hierarchy remains the same when implemented into SAP.

Implement Packages Step
This last step related to the last tab on the ASI loadsheet where the Packages are sent to be implemented to SAP. This should only be done after all changes/errors are corrected.
In cases where the ASI Package being loaded is a new package, the Amplify tool can continue to be used for Implementing.
In cases where the ASI Package has already existed, and the loading aspect is simply creating new actions/maintenance plans in said package, then the Amplify tool shall not be used. Instead, utilize the “ASI Approver_Rev7” tool located in the resources folder. This is a tool that can re-implement packages in ASI, as well as correctly assign user names to the assigned user status in ASI. This is the main reason to use this tool, as the Amplify tool currently does not change user status names.
Once Maintenance Plans are implemented in SAP, one final step needs to be taken in SAP front end. Navigate to IP02 to change MP (or IP15 for list view) in order to change one field in SAP, the Scheduling indicator.
From the MP main page, click on Plan Scheduling parameters.
Under the section “Scheduling indicator” change the selection to “Time – key date” as shown below.
This will allow the MP to correctly time out the work orders to be called. Once this field is selected, the Factory Calendar will automatically populate with A1. This field can now be updated in ASI for data health, however ASI will not need to be re-implemented to SAP, since the factory calendar is now correct in SAP.
Quality Assurance
Once all information is loaded, always pull a new ASI Query (follow the steps in the ASM Query section earlier in this procedure), and look at all the data holistically to identify any errors or blank values. Fix any missing or incorrect values either manually or with an ASI Family loadsheet if there are many errors. To accompany this, utilize the Audit Load Checklist to review every check for a TM, ASM, or ASI load.
The ASI load has the biggest variance of potential errors. Things to look out for are listed below:
Long Text populated correctly for MP/MI/TL/Operations
Call Horizon and Start Date populated correctly
Operation work center is AIPDMX, and plant is 4009 (for all areas)
If asset is statutory, the statutory field is marked Y for all operations
PRT and Material are populated correctly and pushed to SAP correctly

ASM Refresh
Before diving into ASI, the information in ASM must be correct first. The specific “ASM Refresh” task is expanded upon more in the overall ASM procedure, but this section will just be focused on when manual implementations are needed.
ASM Refresh consists of updating the ACTION TITLE, ACTION DESCRIPTION, and ACTION INTERVAL in ASM. This information must be up to date, before being pushed to ASI.
To begin:
Start by gathering the list of strategies and associated actions are desired to be implemented into ASI. Keep in mind an ASM Strategy can house multiple actions. For example, the 440-001-020 Asset Strategy has the External and NDE Strategy which is the example we will use in this section.
Once the appropriate list is identified, we will want to mass update the Action title, Description, and Interval. This is achievable via the ASM Family loadsheet, which will mass update fields. Stat by pulling an ASM query, detailed in this section.
With the ASM query pulled, gather and open the “RTK ASM Family Template” as attached in the resources folder here.
From here, look up by floc, equipment ID, or ASM Strategy to locate the list of actions in the ASM query needing to be updated. For example, searching for “440-001-020 Asset Strategy” in the ASM query will pull up the following:
We see two actions on this Strategy, which is exactly the ones we were looking for. In addition, the Action ENTY KEY is what will be the first data loaded into the “RTK ASM Family Template” under column A.
Next is the Action Name, which depending on the task, has a specific format. For quick reference:
NDE Task: UT NDE INSP [Asset ID] or RT NDE INSP [Asset ID]
EXT Task: EXT VIS INSP [Asset ID]
INT Task: INT VIS INSP [Asset ID]
In this example, the External and NDE Task will need to be changed to EXT VIS INSP 440-001-020 and UT NDE INSP 440-001-020 respectively. Input these into the “RTK ASM Family Template” under column B. Make sure that the action enty keys match that of the old naming convention, i.e. do not mix and match an external task and rename it to UT NDE.
Note: If the action in ASM is already in the correct format, leave that field blank.
Next, populate the description with thee correct format as noted below.
NDE Task: “Execute [UT/RT] thickness readings at designated locations….” etc
EXT Task: “External Visual Inspection per [API Guidance] of likely locations….” etc
INT Task: “Internal Visual inspection per API [API Guidance] guidance of likely areas…” etc
Note: If the Description in ASM is already in the correct format, leave that field blank.
Finally, the last part of the ASM Family Loadsheet is the interval. Usually, the interval listed is correct. (typically 120 or 60months for NDE, and 120, 60, 48, or 36 months for EXT). Usually an interval of just 12 months may indicate the interval is incorrect. Please confirm with the Master Inspection Plans to confirm the correct interval for the tactic. In the following example, 440-001-020 Asset Strategy has 120 month intervals for the UT and EXT task, so this field can be left blank in the loadsheet.
Now, the ASM Family Loadsheet is ready to load. Please refer to this section of the procedure to load the ASM Family loadsheet through the Data Loader module.

Date Aid
The Date Aid is a tool to calculate specific Start Dates, End Dates, and/or Call Dates for a given set of inputs. 
There are three tabs which require three specific inputs. (NOTE: The Interval must be known and is always a required input)
Desired Start Date: The date that has to be entered into the ASI Loadsheet for the Maintenance Plan to start from. This is typically a date in the past, as this is when the interval will start counting from. Usually this is the date that is needed to be calculated and is rarely known beforehand.
Desired Call Date: This is the date that the Work Order (WO) will call (i.e. generate) from the Maintenance Plan. Before this date, the WO number is unknown and the WO cannot be viewed, since it hasn’t been generated. After this date, the WO is accessible and can be then scheduled.
Desired End Date: This is the due date or end of the interval cycle. After this date, the next interval will kick in, where this essentially acts as the start date for the next interval cycle. Between the Call Date and the End Date is the time allotted for the WO to be completed.
Here is an example scenario for how to use the Date Aid tool:
Question: Say there is a 60 month interval regular tactic that needs to be done by 3/6/2023. What should the call horizon be and what start date should be loaded into ASI?
Answer: The Call Horizon is dictated by this table as previously shown in every loadsheet section earlier in this procedure.
Seeing from the table, given a 60 month regular tactic, the call horizon should be 3 months before the Due Date, which gives a call horizon of 95. Plugging the values known in the “Have End Date Tab” gives the following:
Seeing from the tool, the Call Horizon date will kick on 12/3/2022 which is three months before the Due Date of 3/6/2023. More importantly, the calculated start date is 3/6/2018, which is simply 60 months or 5 years before the Due Date. This start date of 3/6/2018 is what will be entered into the ASI Loadsheet and be loaded into ASI.
Loading Aid
The Loading Aid document is a quick reference tool and PRT list in one. The first page expands upon specific Work Center groups for very specific operations such as Pressure Washing, PSV Tactics, and more. It also includes generalized hour/resource information for general inspections. The biggest thing to note is the guidance on Planner Group and Planning Plant information.

Planner Groups shall be those listed within the Functional Location the tactic is tied to. Use the FL_EQ to get exact planner group and planning plant needed per floc.
In addition, the PRT List and PSV PRT List provide references to specific PRT information that is used when building ASI loadsheets. For example, the PRT for an Internal visual on a PV in 512-Smelter has the Document Number, 0000000000000010000234104. This document number references a Word document that is already loaded into the SAP system. This reference simply points to that document when the Maintenance Plan is loaded. The same logic applies to the PSV PRT List.
